# 梦潮产品官网设计规格

## 目标

为第一次接触“梦潮”的访客提供一个公开、可信、易理解的产品介绍网站。访客应能在首屏理解产品定位，在一次短浏览中了解核心能力，并通过静态截图或 GIF 学会完成第一次使用流程。

官网独立部署在公开仓库 `SpringSpiritSecond/dreamtide-website`，不包含或暴露私有仓库 `SpringSpiritSecond/dreamtide` 的 App 源码。

## 产品与受众

- 产品：梦潮（Dreamtide），本地优先的 Android 梦境记录、整理与回看应用。
- 核心用户：第一次了解梦潮、希望记录和回顾梦境的 Android 用户。
- 核心转化：下载最新版 Android APK。
- 次要目标：让用户知道如何“刻梦”、保存、整理和回看。
- 当前边界：无账号注册、无云同步；AI 释梦需要用户自行配置服务。

## 核心文案

### 首屏

- 标题：梦醒以后，仍有迹可循
- 价值主张：记录每一次梦境，整理情绪与片段，再从日历、档案和词云里慢慢回看。
- 产品说明：梦潮是一款本地优先的 Android 梦境记录应用。
- 主操作：直接下载最新版 Android APK
- 次操作：了解梦潮

### 功能

1. 趁记忆还清晰，写下梦  
   用“刻梦”记录正文，支持暂存与正式保存。
2. 为梦留下线索  
   保存后添加标签、隐私标记和注记，也可以获得 AI 参考解读。
3. 在时间里重新遇见  
   从日历、档案与词云回看过去的梦。
4. 梦留在你的设备里  
   当前数据本地保存，并支持导出备份。

### 教程

- 标题：第一次使用梦潮
- 引导：从写下第一场梦开始，四步认识梦潮。
- 步骤：
  1. 下载并安装 Android 版。
  2. 点击“刻梦”，写下梦境。
  3. 保存后添加标签、隐私标记或注记。
  4. 回到“梦潮”，从日历、档案和词云回看。

## 页面信息架构

### 顶部导航

- 左侧显示“梦潮 Dreamtide”品牌印记。
- 桌面端提供“首页、功能、使用指南、下载”四个入口。
- 移动端使用可展开菜单。
- 导航始终保证键盘可操作、焦点清晰，并为固定导航预留内容偏移。

### 首页宣传区

- 标题和价值主张构成左上视觉重心。
- 右侧使用真实的梦潮首页演示，在移动端移动到文案下方。
- 展示主下载按钮、醒目的“了解梦潮”入口、最新版本号和 APK 大小。
- 首屏结束后再次使用整块高对比入口，引导用户进入功能页。
- 背景使用柔和光雾、文字残影和彩色潮汐光晕，不显示虚构功能或统计。

### 功能展示

- 使用四段杂志式错位构图，不使用四张同款卡片。
- 大字号序号、短文案和截图交替穿插。
- AI 释梦只作为“注”中的辅助能力出现，不作为独立主功能。
- 本地优先部分明确说明当前无云同步，并提示用户导出备份。

### 新手教程

- 四个步骤纵向展开。
- 每一步包含编号、标题、两到三行操作说明和一个大幅媒体区域。
- 桌面端图文交错；移动端固定为说明在上、媒体在下。
- 媒体槽保持固定比例，素材加载前后不产生明显布局位移。

### 页面末尾引导与下载区

- 在首页底部使用大幅高对比入口，引导用户进入完整使用教程。
- 再次显示最新版本、系统平台和直接下载按钮。
- “查看全部版本”只作为小型辅助链接，不与下载按钮竞争视觉优先级。
- 明确说明当前数据保存在本机，建议定期导出备份。
- 提供源码与隐私边界的准确描述，不暗示已有云服务或应用商店版本。

## 视觉方向

主题为“雾白诗页 + 彩色潮汐文字装置”。

- 基础色：雾白、浅灰绿、淡青、打字机蓝。
- 强调色：珊瑚红用于主要行动，琥珀用于开始使用，暮紫用于深入探索。
- 渐变保持低饱和与足够文字对比，用于区分关键路径，避免全站颜色完全一致。
- 材质：轻颗粒、柔焦光雾、低对比水波线与文字残影。
- 排版：中文书籍感字体负责标题，现代无衬线字体负责正文和控件；英文仅作辅助印记。
- 层级：远景氛围、中景内容、前景操作三层分明。
- 构图：使用错位、留白和编辑式节奏，避免普通 SaaS 卡片堆叠。
- 图标：统一使用规范 SVG，不使用 Emoji 充当功能图标。

## 动效与交互

- 常规反馈时长为 200–300ms。
- 截图可轻微浮起，文字进入时淡入，水波仅作缓慢低对比漂移。
- hover、press、focus 均有明确反馈且不引发布局跳动。
- 下载按钮在版本请求期间显示可识别的加载状态。
- 所有装饰动效遵守 `prefers-reduced-motion`。
- 触控目标最小高度为 44px。
- 页面锚点滚动应考虑固定导航高度。

## 技术架构

- React + TypeScript + Vite。
- 单页静态网站，不使用运行时后端和复杂路由。
- GitHub Actions 在主分支更新后构建并部署 GitHub Pages。
- Vite base path 适配 `/dreamtide-website/` 项目站点路径。
- 文案、媒体路径和功能数据集中配置，展示组件保持小而清晰。
- 页面使用语义化 HTML，确保键盘导航、焦点顺序与屏幕阅读器基础体验。

## Android 版本与下载

私有 App 仓库的 Release 不能作为公开网页的匿名运行时数据源，也不能在前端嵌入访问令牌。

采用以下公开分发方案：

1. App 发布时，将 APK 同步到 `dreamtide-website` 的公开 GitHub Release。
2. 官网请求：
   `https://api.github.com/repos/SpringSpiritSecond/dreamtide-website/releases/latest`
3. 从 `assets` 中选择文件名以 `.apk` 结尾的资源。
4. 展示 Release 标签、资源大小和发布时间。
5. 主按钮使用 APK 的 `browser_download_url`。
6. 请求失败、限流、无 Release 或无 APK 时，不显示虚假版本；仅提供小型 Releases 辅助入口。

网页不保存 GitHub Token，不请求私有仓库 API。

## 响应式与性能

- 优先检查 375px 宽的手机视口，并覆盖 768px、1024px 和 1440px。
- 不允许移动端横向滚动。
- 媒体使用固定 `aspect-ratio`，避免内容布局位移。
- 首屏资源保持精简；教程 GIF/截图接近视口时再加载。
- 装饰纹理优先使用 CSS 或小型 SVG，不引入大体积背景视频。
- 若 GIF 体积影响首屏或滚动性能，应切换到 WebP 或 MP4，而不降低内容清晰度。

## 异常状态

- 最新版本加载中：显示轻量骨架或短状态，不禁用页面其他内容。
- GitHub API 请求失败：显示简短状态，并提供小型“查看全部版本”辅助链接。
- 尚无 Release：不显示不存在的版本号或文件大小。
- Release 无 APK：保留 Releases 页面入口，并提示当前未找到 Android 安装包。
- 素材缺失：保持最终比例并显示“暂时无法显示此画面”，页面仍可完整阅读。

## 验证与验收

- TypeScript 类型检查通过。
- 生产构建通过，资源路径在 GitHub Pages 子路径下正确。
- 375px、768px、1024px、1440px 均无横向滚动和遮挡。
- 导航、下载、教程锚点支持鼠标、触控和键盘。
- 下载模块覆盖加载成功、请求失败、无 Release、无 APK 四种状态。
- 占位素材与正式素材可通过同名文件直接替换。
- 图片有替代文本；焦点样式可见；颜色对比满足正文阅读。
- reduced-motion 下不播放非必要位移与循环动画。
- 页面不宣称云同步、免费 AI 服务、iOS 版或应用商店版本已经存在。
